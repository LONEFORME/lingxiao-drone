# STM32F103C8T6 + 8 路数字量灰度模块循迹工程

本工程用于两轮差速小车。新 8 路数字量灰度模块安装在小车中部下方，启动时不要求模块已经压在黑线上。

运行顺序如下：

1. 上电后立即通过 I²C 读取模块，并以约 100 Hz 持续获取 8 路数字量。
2. 收到连续有效数据后，PA8 外接状态灯和 PC13 板载 LED 同步常亮，等待 PB1 按键。
3. PB1 第一次出现有效高电平后，程序在 1 秒窗口内统计高电平脉冲数：1～2次选择任务A，4次及以上选择任务B，3次安全回退到任务A。
4. 任务识别后小车原地等待 `START_DELAY_MS = 9000 ms`；任务A的LED快速闪烁，任务B的LED慢速闪烁。
5. 等待结束后，小车以 10 cm/s 先直行。
6. 模块完整检测并离开第一条横向黑线后，开始正常循迹。
7. 程序根据从 A 点开始的编码器平均行程，在 B、C、D 三个位置自动切换四段基准速度。
8. 循迹中检测到真正的弯道时，两盏状态灯同步缓慢闪烁；回到直道后恢复常亮。
9. 进入第二个大弯并越过 D 点粗标记后，至少6路探头见黑才会在 A 点停车；运行中再次按下 PB1 仍可立即停车。
10. 停车后两盏状态灯同步熄灭；如需再次运行，请复位单片机。

## 接线

| STM32F103C8T6 | 8 路数字量灰度模块 I²C |
| --- | --- |
| PB10 / I2C2_SCL | SCL |
| PB11 / I2C2_SDA | SDA |
| 稳定 5V | 5V |
| GND | GND |

传感器独立使用 I2C2。电机驱动板继续使用 I2C1 的 PB6/PB7，因此两块模块不再共用总线，巡线模块异常时不会占住电机控制总线。

| STM32F103C8T6 | 启动/停止按键 |
| --- | --- |
| PB1 | 按下时输入约 3V 高电平 |
| GND | 与按键电源共地 |

PB1 配置为内部下拉输入。松开时必须为低电平，不要向 PB1 输入 5V。

| STM32F103C8T6 | 外接 3.3V 状态灯 |
| --- | --- |
| PA8 | 状态灯正极/信号端，高电平点亮 |
| GND | 状态灯负极/GND |

如果是已经带限流电阻的 3.3V 小灯模块，可直接按上表连接；如果是裸 LED，PA8 与 LED 正极之间必须串联 `220～330Ω` 电阻。GPIO 只能直接驱动低电流指示灯，较大功率灯必须增加三极管或 MOSFET，不能直接接 PA8。

PC13 板载 LED 已恢复，并与 PA8 外接灯显示完全相同的状态。PC13 无需额外接线；如果板载 LED 正常而外接灯不亮，说明程序正在运行，应重点检查 PA8 接线、灯的正负极和工作电流。

| STM32F103C8T6 | 电机驱动板 |
| --- | --- |
| PB6 / I2C1_SCL | SCL |
| PB7 / I2C1_SDA | SDA |
| GND | GND |

电机板 I2C 地址为 `0x26`。1 号电机是右轮，2 号电机是左轮；当前实车映射为右轮前进使用负指令、左轮前进使用正指令。

程序使用驱动板 `0x06` 编码器闭环速度控制，初始化参数为：JGB37-520、减速比 30、磁环线数 11、轮径 68 mm、死区 1900。停车时通过 `0x07` 清零四路 PWM。

## A、B、C、D 点和分段速度

小车从 A 点顺时针运行：

- A：左侧直线下端，也是起点和终点横线。
- B：左侧直线上端。
- C：右侧直线上端。
- D：右侧直线下端。

赛题尺寸中 A→B 为 1500 mm，B→C 为半径 750 mm 的上半圆，因此：

```text
A→B = 1500 mm
A→C = 1500 + π×750 ≈ 3856 mm
A→D = 3856 + 1500 = 5356 mm
```

B、C、D 的速度切换不依赖粗点，而是使用编码器里程。程序在中置传感器确认经过 A 点横线时读取左右轮编码器作为起点，之后每次读取两轮相对上一次的变化量并累计行程，再利用左右轮平均行程判断车体中心行程。该算法允许底层编码器方向为负，并会过滤计数器回绕或异常读取造成的单次大跳变，因此里程只会增加、不会在后半程倒退。这样也不会把“车头到中置传感器”的安装距离误算进各段路程：

- 任务A：A→B、B→C、C→D、D→终点依次为 `50 / 150 / 250 / 200 mm/s`。
- 任务B：A→B、B→C、C→D、D→终点依次为 `250 / 200 / 50 / 180 mm/s`。

左右轮的 PD 转向修正一加一减。程序限制弯道内侧轮不低于 `TRACK_MIN_INNER_SPEED`，并通过 `TRACK_SPEED_SLEW_STEP` 限制每个控制周期的速度变化，避免内侧轮在停转、反转与前进之间突然切换。弯道上使用两轮平均编码器行程，也能近似表示车体中心沿轨迹前进的距离。

为避免 B、C、D 的粗点被误认为终点，终点识别还增加了两级保护：

- A→D 的理论行程为 `3856 + 1500 = 5356 mm`。
- 再向第二个大弯内行进 `FINISH_ARM_AFTER_D_MM = 1000 mm`，即累计约 6356 mm 后，才启用终点检测。
- 启用后必须至少 `FINISH_LINE_MIN_SENSORS = 6` 路探头连续见黑达到 `FINISH_STABLE_MS`，才会停车。
- 无论终点横线是否成功识别，编码器累计里程达到 `ODOMETRY_STOP_DISTANCE_MM = 7592 mm` 时都会立即停车，即按当前调参在 7712 mm 总路程的终点前约 120 mm 停车。

## 传感器协议

本工程严格按照官方 `STM32最小系统板循迹例程` 的 I²C 驱动：

```text
STM32接口：I2C2（PB10=SCL、PB11=SDA）
总线速度：100 kHz
7位设备地址：0x2E
数字量寄存器：0x02
读取长度：1 字节
```

返回字节含义：

```text
Bit7 Bit6 Bit5 Bit4 Bit3 Bit2 Bit1 Bit0
 8路  7路  6路  5路  4路  3路  2路  1路
```

官方例程定义 `0xFF=全白、0x00=全黑`，因此当前程序使用 `0=黑线、1=白底`。1 路应安装在车体左侧、8 路在右侧；如果实车方向相反，只需把 `LINE_SENSOR_REVERSED` 改为 `1`，不需要交换八路权重。

之前针对另一款 UART 灰度模块提到的 `0x57`、9600 波特率以及 K1/K2 指示灯6/7设置，不适用于这块 I²C 模块。

## 启动等待优化

程序上电后马上读取传感器，并满足以下两个条件后进入就绪状态：

- 已经过最短 `SENSOR_READY_MIN_MS`（默认 500 ms）。
- 已收到至少 `SENSOR_READY_MIN_FRAMES` 个新鲜有效帧（默认 5 帧）。

因此模块正常时通常约 0.5 秒即可就绪；如果模块确实启动较慢或没有正常通信，程序仍会继续闪灯等待，不会在没有数据时误启动。

传感器就绪后，按下 PB1 的启动时序为：

```text
PB1 有效按下
  → 立即发送 DCP v1 CAR_START(task_mode=2, ACK_REQUIRED)
  → PA8 外接灯和 PC13 板载 LED 同步快速闪烁，电机保持停止，等待 11 秒
  → 未收到 ACK 时每 500 ms 重发同一 session/sequence
  → 11 秒到达，两盏状态灯同步恢复常亮，小车开始前进
```

重复帧使用相同会话号和序号，无人机端应按 DCP 协议幂等处理，不能因为收到多帧而重复启动任务。

## 起点和终点横线

- 启动后以 `START_APPROACH_SPEED` 直行，此时全白不会触发丢线停车。
- 至少 `CROSSLINE_MIN_SENSORS` 个探头同时见黑，并持续 `START_LINE_STABLE_MS`，确认遇到起点 A 横线。
- 横线消失并持续 `START_CLEAR_STABLE_MS` 后，才真正启动循迹控制器。
- 只有进入第二个大弯后的终点检测窗口内，至少6路探头见黑并持续 `FINISH_STABLE_MS`，才判定回到终点 A。

## 弯道识别说明

弯道灯不会根据左右轮速度是否相等来判断，而是使用 8 路传感器计算出的黑线位置误差：

- 误差绝对值达到 `CURVE_ENTER_ERROR`；
- 误差方向保持一致；
- 连续达到 `CURVE_ENTER_STABLE_MS`；

三个条件同时成立才进入弯道状态。回到中心附近并持续 `CURVE_EXIT_STABLE_MS` 后退出弯道状态。这样可滤掉直道上轮速不一致造成的大部分短暂偏转和来回修正。

需要注意：仅使用一排横向传感器，无法从几何上百分之百区分“持续严重跑偏”和“真实弯道”。如果直道跑偏一直持续、并且黑线长时间停在同一侧，它仍可能被识别为弯道。实车应先调好两轮基础一致性，再根据 LED 表现调整阈值；若以后要求严格识别赛道曲率，需要增加前后两排传感器、编码器航向估计或 IMU。

## 集中调参位置

实车常用参数已经集中到 `User/main.c` 文件最前方的“实车常用参数集中调节区”。修改等号右侧的数值即可，其他源文件会直接使用这些变量：

- `TASK_SELECT_WINDOW_MS`、`TASK_B_MIN_PULSES`：PB1任务识别窗口和任务B的最少脉冲数。
- `TASK_A_SPEED_*`：任务A的四段速度，当前为 50、150、250、200 mm/s。
- `TASK_B_SPEED_*`：任务B的四段速度，当前为 250、200、50、180 mm/s。
- `B_POINT_DISTANCE_MM`：从 A 到 B 的编码器平均行程阈值，当前 1500 mm。
- `C_POINT_DISTANCE_MM`：从 A 到 C 的编码器平均行程阈值，当前 3856 mm。
- `ODOMETRY_UPDATE_MS`：编码器行程检查周期，当前 100 ms。
- `ODOMETRY_MAX_STEP_COUNTS`：单次编码器变化量上限，当前 2048；超过时按回绕或异常读数过滤。
- `D_POINT_DISTANCE_MM`：从 A 到 D 的理论行程，当前约 5356 mm。
- `ODOMETRY_STOP_DISTANCE_MM`：从 A 起算的编码器硬停车里程，当前 7592 mm，即总路程 7712 mm 前 120 mm。
- `FINISH_ARM_AFTER_D_MM`：越过 D 后再进入第二大弯多少距离才允许识别终点，当前 1000 mm。
- `FINISH_LINE_MIN_SENSORS`：终点要求同时见黑的探头数，当前 6。
- `START_APPROACH_SPEED`、`START_MARKER_SPEED`：A 点前进和跨线速度，当前分别为 100 mm/s 和 130 mm/s。
- `TRACK_KP_NUM`、`TRACK_KD_NUM`：循迹 PD 参数。
- `TRACK_TURN_LIMIT`：最大转向修正量。
- `TRACK_MIN_INNER_SPEED`：弯道内侧轮最低前进速度，当前 30 mm/s。
- `TRACK_SPEED_SLEW_STEP`：每个控制周期单轮允许的最大速度变化，当前 15 mm/s。
- `TRACK_WEIGHTS[8]`：从车体左侧到右侧的8个探头位置权重。
- `CROSSLINE_MIN_SENSORS`：横线判定需要同时见黑的探头数，当前 6。
- `START_LINE_STABLE_MS`、`START_CLEAR_STABLE_MS`：起点横线进入/离开确认时间。
- `FINISH_STABLE_MS`：至少6路见黑后的终点确认时间，当前 10 ms。
- `CURVE_ENTER_ERROR`、`CURVE_ENTER_STABLE_MS`：进入弯道的阈值和持续时间。
- `CURVE_EXIT_ERROR`、`CURVE_EXIT_STABLE_MS`：退出弯道的阈值和持续时间。
- `CURVE_LED_BLINK_MS`：弯道 LED 慢闪半周期，当前 500 ms。
- `SENSOR_READY_MIN_MS`、`SENSOR_READY_MIN_FRAMES`：传感器快速就绪条件。
- `TASK_A_LED_BLINK_MS`、`TASK_B_LED_BLINK_MS`：任务识别后的A任务快闪和B任务慢闪半周期。
- `LINE_QUERY_INTERVAL_MS`：I²C 读取间隔，当前 10 ms。
- `LINE_SENSOR_REVERSED`：1 路和 8 路方向反装时设为 1。
- `LINE_BLACK_LEVEL`：黑线对应的数字电平，当前为 0。
- `LOST_STOP_MS`、`LOST_SEARCH_BASE`、`LOST_SEARCH_TURN`：丢线搜索参数。
- `START_DELAY_MS`：任务识别完成后小车原地等待时间，当前 9000 ms。

底层硬件参数仍放在 `User/app_config.h`，一般接线不变时不需要修改：

- `LINE_I2C_ADDR_7BIT`、`LINE_I2C_DIGITAL_REG`、`LINE_I2C_CLOCK_HZ`：巡线模块 I2C2 参数。
- `MOTOR_*`、`RIGHT_WHEEL_*`、`LEFT_WHEEL_*`：电机型号、68 mm 轮径、编码器和轮子方向。

首次测试建议先架空车轮，确认左右轮累计编码器的前进方向都为正，再落地测量各速度切换点的实际距离。轮胎压缩和打滑会产生少量误差，可直接微调 `B_POINT_DISTANCE_MM`、`C_POINT_DISTANCE_MM` 和 `D_POINT_DISTANCE_MM`。
